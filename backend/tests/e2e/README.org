#+TITLE: Limn 端對端（e2e）測試
#+OPTIONS: toc:nil

* 這些測試是什麼

=backend/tests/= 目錄底下原本就有兩層測試：

| 層級        | 驅動方式                              | 測到的層            |
|-------------+---------------------------------------+---------------------|
| unit        | mock client（in-memory FIFO）         | 純 Lisp 邏輯        |
| integration | 真的 Limn binary + 原始 wire JSON     | C++ + bridge 協議    |

兩層都*刻意*跳過真正的 backend Lisp client（=limn.lisp= 等等）。這對保持測試
聚焦是好事，但結果就是第三層沒測：**Lisp client + framework runtime
照著真正使用者的方式運作**這層。

=e2e/= 目錄就是補這個洞。每個測試會：

1. 把真的 =limn= binary spawn 起來
2. 在測試 process 裡載入 *真實的* backend 模組（=limn.lisp= 之類）
3. 呼叫 =(limn:start …)= 用跟使用者一模一樣的方式 setup
4. 透過 Lisp 層 API + Qt 層 input 注入跑出一個情境
5. 驗證觀察得到的副作用（response 資料、side effects、log 檔）

* 什麼時候要加 e2e 測試

當一個功能橫跨多層、各層分開測都會漏掉問題的時候加。例子：

- batch 8（C-g）：keypress → Qt filter → backend hook → keymap walk →
  defcommand → reader → 動態綁定的 canceller → cancel → handler-case。
  *每一個* unit/integration 測試都至少 mock 掉或跳過了其中一個環節。
- batch 9（init.lisp）：模組載入順序 + start sequence + 真正的檔案 IO。

如果一個聚焦的 unit test 就夠了，就不要開 e2e。

* 執行方式

#+begin_src bash
# 跑所有 e2e 測試：
backend/tests/e2e/run-e2e.sh

# 跑單一個：
sbcl --no-userinit --no-sysinit --non-interactive \
     --load backend/tests/e2e/batch8-cg-qt.lisp
#+end_src

每個 script 過了 exit 0、失敗非 0；會印一行明顯的 VERDICT 行讓你 grep。

* 兩種版本：-qt 和 -os

每個情境都會做成成對的兩個 driver，目的是同一個測試打到兩個層：

| suffix          | 注入機制                                          | 涵蓋層                                    | 跑得起來的環境           |
|-----------------+---------------------------------------------------+-------------------------------------------+--------------------------|
| =batch*-qt.lisp= | =test/inject-qt-key=（QApplication::sendEvent）   | Qt event filter ↓ 整條 Lisp 層            | 任何 host（macOS / Linux）|
| =batch*-os.lisp= | =xdotool key=（真的 X11 input event）             | + X server → XInput → Qt xcb              | 限 Linux container       |

=-os= 這個版本就是讓測試真的覆蓋到「真實使用者按一個鍵」的同一條鏈
路。我們選 Linux + Xvfb + xdotool 是因為：

- macOS 的 OS 層注入需要 Accessibility 系統權限（被擋住）
- Linux X11 input 子系統沒這道權限關卡
- Container 讓測試環境可重現

兩種版本同一個情境都該 pass —— 它們不是冗餘，而是同一條鏈路的不同層。

* 執行方式（兩種版本）

#+begin_src bash
# 全部 Qt 層測試（macOS / Linux，不需要 container）：
backend/tests/e2e/run-e2e.sh

# 全部 OS 層測試（一定要在 Limn container 裡）：
backend/tests/e2e/run-os-e2e.sh

# 兩種都跑，需要的話順便 build / 起 container：
backend/tests/run-all-tiers.sh
#+end_src
