** bookmark everywhere — 跨 buffer 可命名書籤

把 Sioyek 既有的「單一 PDF、單字元 key」bookmark 升級成 Emacs
=bookmark.el= 等價的「跨 buffer、可命名、session 持久化」層。原本
的 PDF-only bookmark （limn-pdf-mode §E）保留，兩者語意分離、互不
覆寫；新 layer 走 =C-x r m / b / l / d / M=，舊 layer 繼續用 =m a=
/ ='a= register-style。

新模組（純 Lisp，C++ 一行不改）：

*** =limn/bookmark= (=backend/limn-bookmark.lisp=)
- *Struct*：=(:name STRING :handler SYMBOL :record PLIST)=
- *Store*：global hash =*bookmarks*=，upsert by name、list 回傳 by-
  name sorted（UI deterministic）
- *Handler registry*：mode-symbol → jump-fn；每個 mode 註冊自己的
  跳轉邏輯，bookmark-jump dispatch
- *Record-fn registry*：mode-symbol → record-fn；capture current
  location，給 bookmark-set 用
- *Persistence*：=~/.limn/bookmarks.lisp=（s-exp，原子寫入 .tmp +
  rename），CJK / 非 BMP 安全

*** =limn/bookmark-cmds= (=backend/limn-bookmark-cmds.lisp=)
- =M-x bookmark-set / -jump / -delete / -rename / -list / -save / -load=
  全部走 =defcommand= 在 :cl-user 命名空間，M-x completion 看得到
- =install-bookmark-bindings=：=C-x r m/b/l/d/M= 綁在 global-keymap
  上（由 =install-defaults= 呼叫，符合 [feedback-fix-discipline]
  directive 5 keymap 紀律）
- =current-handler-symbol=：由 runtime/mode 解析 focused buffer 的
  major mode，給 bookmark-set 做 record-fn dispatch

*** =limn/bookmark-handlers= (=backend/limn-bookmark-handlers.lisp=)
- text-mode / org-mode 共用 =(:file PATH :position N)= shape
- pdf-mode 用 =(:path PATH :page P :y-offset Y :x-offset X)= shape
- Jump：text 走 =find-file= + =buffer/cursor-set= wire；pdf 走
  =find-file= + =view/set :page :offset-y :offset-x= wire
- 全部走 vtable（=*text-record-fn*= / =*pdf-jump-fn*= 等）→ 單元測試
  可純 mock，不需 live binary

*** Wireup

** logging — hierarchical namespace + wire mirror

把 v0.23 的 =*Messages*= ring 升級成：
- *log-record struct* — ring 改存 =(time level ns text)= struct (=get-records=
  回 struct list；=get-messages= 仍回 string、backward compat)
- *Hierarchical namespace* — ns 是 dotted symbol，例如
  ='pdf-mode.annotation.edit=；leaf → root → =*default-log-level*=
  繼承解析。canonical key 是 SYMBOL-NAME，package-independent
- *Per-ns verbosity* — =limn/log:set-level= / =unset-level= / =get-level=
  / =effective-level= / =with-log-levels= macro
- *Wire mirror* — =*log-wire-sender*= hook，由 =limn:start= 安裝；
  per-message 把通過 effective-level 的訊息發 =message/log= notify、
  寫進 C++ =*messages*= GapBuffer。格式 =[HH:MM:SS LEVEL ns] text=。
  =limn:stop= 卸下。Sender NIL 時純 ring 行為 (unit tests / pre-session)
- *單一 source of truth* — Lisp ring 跟 C++ GapBuffer 不再分歧；REPL
  =buffer/text "*messages*"= 跟 =get-records= 看到同一份內容
- *新 keyword 呼叫形* — =(message :level :warn :ns 'pdf-mode "x")=；
  舊 shape ((message "x") / (message :warn "x")) 完全相容

三個檔案：
- =backend/limn-log.lisp= 重寫 (struct + ns hash + wire-sender)
- =backend/limn.lisp= =start= / =stop= 安裝/卸下 =*log-wire-sender*=
- =sioyek/pdf_viewer/limn_command.cpp= C++ widget 顯示修補（下段）

C++ widget 顯示修補：

之前 =sync_text_widget= 對所有 =*= 開頭的 buffer 一律 skip
(=startsWith('*')=)、理由是 chrome buffer 屬於 =LimnChromeBar=。但這
對 =*messages*= 不成立 —— 它是純滾動 log buffer、本該用主
QPlainTextEdit 顯示。改成精準 deny list (只擋 =*echo-area*= /
=*minibuffer*=)、放行 =*messages*=；對 =*messages*= 額外 cursor 跳
end + =ensureCursorVisible=（Emacs *Messages* 慣例的 auto-tail）；
=cmd_message_log= / =cmd_message_echo= 末尾各加 =sync_text_widget(
"*messages*")=、每筆 append 即時 refresh widget。

User 操作：=M-x switch-to-buffer= → =*messages*= → 主視窗變成滾動
log view、之後 =(message ...)= 即時 append + auto-scroll 到底。

** 實作筆記

  production 第一次 START 時連到真 wire

* v0.35.0 — file-notify + auto-revert + process I/O coding
:PROPERTIES:
:DATE: 2026-05-24
:END:

把「外部世界變化」這條打通：檔案被別的程式改、subprocess 用不同
編碼講話，現在都進得了 Limn 不會破。三件事全部純 Lisp、C++ 一行
不改、只多 Dockerfile 一個 nix package（=inotify-tools=）。

** §A file-notify — OS 檔案監視（=backend/limn-file-notify.lisp=）
- API 對齊 Emacs =filenotify.el=：=file-notify-add-watch= /
  =file-notify-rm-watch= / =file-notify-valid-p=
- 兩條路徑：
  - **OS helper subprocess** — 開機 probe =inotifywait=（Linux）/
    =fswatch=（macOS），spawn 一個長住的 watcher、stdout 每行一個
    event、parse 後 deliver 到對應 callback
  - **Polling fallback** — 沒有 helper 時 =stat= mtime + size、
    用 =dispatch-poll-tick= 推進；任一變化觸發 =:modified=
- 五個 action keyword：=:created= =:deleted= =:modified= =:renamed=
  =:attribute-changed=（=:attribute-change= flag 過濾後兩者以外的事件）
- Helper 死了 reaper 重啟，watch 不丟（=helper-respawn-count= 可
  inspect、=simulate-helper-exit= 是 test hook）
- Callback 包在 =limn/error:%call-with-protection= 內，一個壞 cb
  不會打斷整條 dispatcher
- Directory watch：watch =/tmp/dir=、=/tmp/dir/file= 變化也派送
  （Emacs 慣例）
- 完整 vtable（=*file-notify-helper-spawn-fn*= /
  =*file-notify-helper-probe-fn*= / =*file-notify-stat-fn*= /
  =*file-notify-exists-p-fn*= / =*file-notify-now-fn*=）讓 unit
  tests 完全不碰 OS

** §B auto-revert-mode（=backend/limn-auto-revert.lisp=）
- =(auto-revert-mode BUF)= toggle 單 buffer
- =(global-auto-revert-mode 1)= 對所有 file-backed buffer 啟用、
  =-1= 全關
- =(auto-revert-tail-mode BUF)= log-tail 模式：revert 後 cursor
  自動 =goto-char point-max=
- 規則（與 Emacs 等價）：file-notify 報 =:modified= 或
  =:attribute-changed= → 若 buffer **沒有未存改動** 自動
  =revert-buffer :confirm nil=；**有 modified** → =message= 警告
  但不動 buffer
- =(tick)= reconciliation pass：dead buffer 自動拔 watch、global
  mode 開時自動補新 file buffer
- =*auto-revert-interval*= 預設 5 秒（無 file-notify 時 fallback
  polling 用）
- vtable：=*revert-buffer-fn*= / =*buffer-modified-p-fn*= /
  =*visited-file-name-fn*= / =*buffer-list-fn*= /
  =*file-notify-add-fn*= / =*file-notify-rm-fn*= 等，
  全部可注入

** §C process I/O coding（擴 =backend/limn-process.lisp=）
- =make-process= 多三個 kwarg：
  - =:coding-system 'utf-8= — 雙向
  - =:decode-coding-system 'big5= — 只解 stdout
  - =:encode-coding-system 'utf-8= — 只編 stdin
- 全域：=*default-process-coding-system*= = ='(utf-8 . utf-8)=
  （read . write）；spawn 沒指定 coding 時套用
- buffer-local：=*buffer-process-coding-system*= placeholder
  (when 一個 buffer 接到 process 時 layer 可優先讀)
- 兩個新 accessor：=process-decode-coding= / =process-encode-coding=
- 實作：底層 SBCL stream 仍 =:external-format :latin-1=（raw bytes
  per-char），讀回時把 char-code 重新打包成
  =(vector (unsigned-byte 8))=，走 v0.31 =limn/coding:decode-coding-string=
  解；寫 stdin 反向。
- **Decode failure 安全**：encode failure 升 error 給 caller；
  decode failure（如 0xFF 餵 utf-8）lossless fallback 回 latin-1
  字串（既有 =process-a7-non-utf8-bytes-do-not-crash= 仍綠）
- 向下相容：不傳 coding kwarg 走 default utf-8 pair → ASCII 完全
  不受影響（既有 116 process tests 全綠、0 regression）
