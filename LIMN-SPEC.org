* Limn 規格書 v0.8

Limn 是一個由 Common Lisp（SBCL）控制的顯示框架。
Backend（Lisp）透過 Bridge（Unix socket + JSON）驅動 Frontend（Qt）。

Qt 是目前唯一的 Frontend 實作，但架構設計為可替換：
GTK、terminal（sixel）、headless 等均可實作同一套 Bridge 協議。

** 一、核心概念

| 概念    | 定義                                           | 類比                  |
|---------+------------------------------------------------+-----------------------|
| frame   | OS 層級的獨立視窗                              | Emacs frame           |
| window  | frame 內的視埠，顯示一個 buffer                | Emacs window          |
| buffer  | Limn 的基本內容單元，持有內容與其狀態          | Emacs buffer          |
| engine  | 處理特定類型 buffer 的後端機器                 | Emacs 沒有直接對應    |
| mode    | buffer 的 keymap + hook + 行為集合（細節 §1.1） | Emacs major/minor mode |

關係：

#+begin_src
frame  ──包含──▶  window（可分割為多個，含 floating window）
window ──顯示──▶  buffer（多個 window 可顯示同一個 buffer）
buffer ──由────▶  engine 管理（一種 engine 可管理多個 buffer）
buffer ──套用──▶  mode（一個 major、零或多個 minor，決定使用者怎麼互動）
#+end_src

*** 1.1 模式（Mode）

Mode 是「在這個 buffer 裡按某個鍵會怎樣」的命名 bundle：

- 一個 keymap（可繼承 parent keymap）
- enter / exit hooks
- 可選的 buffer-local 變數
- 用於 modeline 顯示的短名

每個 buffer 有**恰好一個** major mode 與 **零個以上** minor modes。
Keymap 查詢順序：minor modes（依啟用順序新到舊）→ major mode → global。

**Mode 與 engine 不同**：engine 決定 buffer **裝什麼內容**（PDF？HTML？
純文字？），mode 決定 buffer **使用者怎麼互動**。同一個 PDF buffer
可以套 =pdf-mode= 或 =presentation-mode=，內容不變、互動規則換了。

Mode 的定義跟切換邏輯都在 backend；frontend 只透過 =modeline/set= 等
指令更新 chrome 顯示。Mode 系統的 Backend 端慣例見 §9.1。

*** 1.2 Chrome primitives

「Chrome」指 framework 本身的視覺零件，跟 buffer 內容區分。任何 Limn
frontend 必須提供四個 chrome 元素，**前三個是 text-engine buffer，第
四個是 window 的顯示屬性、不是 buffer**——這個區別跟 Emacs 一致。

**Buffer-backed chrome（三個）**：

- **Minibuffer**：universal input prompt。=M-x=、=/=、=C-x C-f=、=M-:=
  等所有從使用者讀字串的場景共用同一個 buffer，有保留 ID
  =*minibuffer*=，有自己的 keymap（=minibuffer-mode=）。指令見 §5.4。
- **Echo area**：minibuffer 閒置時的同一條畫面區域，印 message / error /
  hint。是 buffer，保留 ID =*echo-area*=；內容是「目前要顯示的單行」，
  =message/echo= 寫進去同時也 append 到 =*messages*=。對應 Emacs 的
  =\ *Echo Area 0*= / =\ *Echo Area 1*=（前綴空格的 hidden buffer，且
  做 double-buffering——後續優化）。
- ***Messages***：累積所有 message 的 buffer，保留 ID =*messages*=。可
  以用 =buffer/text :|buffer-id| "*messages*"= 直接拿歷史。

三者統一好處：使用者跟 framework 都用同一套 =buffer/*= 指令訪問，未來可
以套 mode（=messages-mode=、=minibuffer-mode=）、可以用 =view/overlays=
高亮、可以無痛 redirect 到任何其他 text-engine 用例。

**Window decoration（不是 buffer）**：

- **Modeline**：每個 window 底部一條 status line，顯示**關於 buffer**
  的資訊（mode 名、buffer 名、scroll 位置等）。**不**是 buffer——是
  per-window 的 format string，與 Emacs 的 =mode-line-format= 對應；
  同個 buffer 在不同 window 可有不同 modeline。指令見 §5.6。

Text engine 是 bundled engine 之一，所以以上三個 buffer 一律存在、可
透過 =buffer/text= 訪問。詳見 §7.6。

** 二、架構

Limn 是一個 async event-driven loop，概念上類似 REPL，但不是嚴格的
sequential READ→EVAL→PRINT→LOOP。事件異步抵達、可以排隊；
多個 EVAL/PRINT 可以並行進行，靠 request id 對應結果。

#+begin_src
READ  → events 從 Frontend 異步抵達，可排隊
          → Bridge 推送給 SBCL

EVAL  → Lisp handler 處理事件
          → Bridge 送出一個或多個指令（可與其他 event 的 EVAL 並行）

PRINT → Frontend 執行指令，更新畫面
          → Bridge 以相同 id 回傳結果給 SBCL
#+end_src

整體結構：

#+begin_src

│                          Limn                               │
│  ┌──────────┐    ┌────────────────┐    ┌───────────────┐   │
│  │ Backend  │    │     Bridge     │    │   Frontend    │   │
│  │  (SBCL)  │◀──▶│  Unix socket  │◀──▶│  (Qt 或其他)  │   │
│  │          │    │  JSON + ID     │    │               │   │
│  │ 所有邏輯 │    └────────────────┘    │  ┌─────────┐  │   │

*** 訊息處理與並行

Bridge 的 request/response 設計（每條訊息帶唯一 =id=）允許
SBCL 同時有多個 pending request，不須依序等待。

SBCL 端如何處理並行（單一訊息迴圈、thread pool 等）
屬於 backend 實作細節，本規格不強制規定。
若某個 request 需要長時間運算，backend 應在獨立執行緒中處理，
避免阻塞主事件迴圈。

*** 嵌入模式（Embedding Mode）◇ 長期目標

目前 Bridge 透過 Unix socket 傳遞訊息。未來可加入嵌入模式：
SBCL 透過 CFFI 直接呼叫 Frontend 的 C 函式，
繞過 socket 序列化，適用於需要極低延遲的場景（如即時渲染回饋）。

嵌入模式與 socket 模式使用相同的邏輯 API，
差別僅在傳輸層。切換時 backend 程式碼無需改寫。

** 四、Bridge 協議

*** 4.1 傳輸層

- 協議：Unix domain socket
- 路徑：=/tmp/limn-<PID>=（含 PID 以支援同時跑多個 Limn 實例）
- 格式：UTF-8，每行一個 JSON 物件（以 =\n= 分隔）
- 方向：雙向，同一條連線

*** 4.2 訊息類型

**** Request（Backend → Frontend）

#+begin_src json
{"id": "r42", "cmd": "view/set", "win-id": "w1", "page": 5}
#+end_src

- =id=：唯一字串，由 Backend 生成
- =cmd=：指令名稱
- 其餘欄位為指令參數

**** Response（Frontend → Backend）

#+begin_src json
{"id": "r42", "ok": true,  "data": { ... }}
{"id": "r42", "ok": false, "error": "page out of range"}
#+end_src

*規則*：所有成功回應的 payload 一律放在 =data= 欄位下，即使只有一個欄位。
即使不需要回傳資料，=data= 可省略（=={"id":"r1","ok":true}== 合法）。
失敗回應的 =error= 是字串，描述具體原因。

**** Event（Frontend → Backend，主動推送，無 id）

#+begin_src json
{"event": "key", "frame-id": "f1", "key": "j", "mods": []}
#+end_src

所有事件都帶 =frame-id=，表示事件來源的 OS 視窗。
需要指明具體視窗的事件（如 mouse-click）同時帶 =win-id=。

*** 5.1 bridge/ ── 視窗、frame、engine 管理

*** 5.2 view/ ── 視埠顯示

所有 engine 都必須實作。=win-id= 決定路由到哪個 engine。

=view/set= 的通用欄位（所有 engine 適用）：

| 欄位       | 類型  | 說明                    |
|------------+-------+-------------------------|
| =page=     | int   | 頁碼（0-based）         |
| =offset-y= | float | 垂直捲動（文件座標）    |
| =offset-x= | float | 水平捲動（文件座標）    |
| =zoom=     | float | 縮放倍率                |

Engine 專屬參數放在 =engine-params= 中，engine 自行解讀，
不認識的欄位忽略：

#+begin_src json
// 設定視埠（通用欄位 + engine 專屬參數）
{"id":"r10", "cmd":"view/set", "win-id":"w1",
             "page":5, "zoom":1.5,
             "engine-params":{"dark-mode":true, "rotation":90}}
→ {"id":"r10", "ok":true}

// 查詢視埠狀態
{"id":"r11", "cmd":"view/get", "win-id":"w1"}
→ {"id":"r11", "ok":true,
   "data":{"buffer-id":"b1", "page":5, "offset-y":1234.5,
           "zoom":1.5, "engine-params":{"dark-mode":true}}}

// 疊加層（Lisp 決定畫什麼，engine 負責畫）
{"id":"r12", "cmd":"view/overlays", "win-id":"w1",
             "layers":[
               {"type":"rect",
                "page":5, "rect":[x0,y0,x1,y1],
                "color":"#FFD700", "opacity":0.4},
               {"type":"rect",
                "page":5, "rect":[x0,y0,x1,y1],
                "color":"#FF6B6B", "opacity":0.6},
               {"type":"line",
                "page":5, "from":[x1,y1], "to":[x2,y2],
                "color":"#0000FF", "width":2, "opacity":1.0},
               {"type":"text",
                "page":5, "pos":[x,y], "text":"Note",
                "color":"#000000", "size":12, "opacity":1.0}
             ]}
→ {"id":"r12", "ok":true}
#+end_src

=view/overlays= 支援的 type：=rect=、=line=、=text=。
所有 type 都支援 =color=（hex RGB）與 =opacity=（0.0–1.0）。
這是 Lisp 控制視覺呈現的核心原語，所有 engine 都必須實作。

*** 5.3 buffer/ ── buffer 內容操作

engine 依能力實作。=buffer/open= 回應中的 =supports= 欄位
列出該 engine 支援哪些 buffer/ 指令。

#+begin_src json
// 開啟內容，建立 buffer
{"id":"r20", "cmd":"buffer/open",
             "engine":"mupdf", "path":"/tmp/paper.pdf"}
→ {"id":"r20", "ok":true,
   "data":{"buffer-id":"b1", "page-count":42,
           "supports":["buffer/toc","buffer/text",
                       "buffer/links","buffer/render"]}}

{"id":"r21", "cmd":"buffer/close", "buffer-id":"b1"}

// 目錄 / 結構
{"id":"r30", "cmd":"buffer/toc", "buffer-id":"b1"}
→ {"id":"r30", "ok":true,
   "data":[{"title":"Chapter 1","page":0,
            "children":[{"title":"1.1","page":2,"children":[]}]}]}

// 頁面文字（含邊界框，供 Lisp 做搜尋）
// 注意：不適用於 audio、video 等非文字 engine
{"id":"r31", "cmd":"buffer/text", "buffer-id":"b1", "page":5}
→ {"id":"r31", "ok":true,
   "data":{"words":[{"text":"hello","rect":[x0,y0,x1,y1]}, ...]}}

// 連結
{"id":"r32", "cmd":"buffer/links", "buffer-id":"b1", "page":5}
→ {"id":"r32", "ok":true,
   "data":[{"type":"internal","dest-page":12,"rect":[x0,y0,x1,y1]},
           {"type":"uri","uri":"https://...","rect":[x0,y0,x1,y1]}]}

// 整頁渲染 → PNG base64
{"id":"r40", "cmd":"buffer/render",
             "buffer-id":"b1", "page":5, "dpi":150}
→ {"id":"r40", "ok":true, "data":{"png":"iVBORw0K..."}}

// 矩形截圖
{"id":"r41", "cmd":"buffer/render-region",
             "buffer-id":"b1", "page":5,
             "rect":[x0,y0,x1,y1], "dpi":150}
→ {"id":"r41", "ok":true, "data":{"png":"..."}}

// Metadata
{"id":"r42", "cmd":"buffer/metadata", "buffer-id":"b1"}
→ {"id":"r42", "ok":true,
   "data":{"title":"...","author":"...","page-count":42,"format":"pdf"}}

// 多頁搜尋（v0.27 新增）—— 走 MuPDF =fz_search_page= 逐頁掃。
// rects 已 page-normalize 為 0..1 浮點（同 view/overlays 的座標系）。
// case-sensitive 預設 false；mupdf 預設不分大小寫，true 走自訂 stext 路徑。
{"id":"r80", "cmd":"buffer/search",
             "buffer-id":"b1", "query":"deep learning",
             "case-sensitive":false}
→ {"id":"r80", "ok":true,
   "data":{"hits":[{"page":3, "rects":[[0.12,0.34,0.45,0.36],
                                       [0.12,0.41,0.45,0.43]]},
                   {"page":7, "rects":[[0.20,0.18,0.50,0.20]]}]}}
#+end_src

**Buffer 編輯**（text engine 適用；非文字 engine 一律回 =not supported=）：

文字類 buffer 有一個 cursor (offset，0-based 字元位置)。編輯指令以
cursor 跟 range 為核心、跟所有 text-engine buffer 通用——=*minibuffer*=、
=*messages*= 之類的 chrome buffer 跟使用者透過 =engine=text= 開的 buffer
共用同一套協議。

#+begin_src json
// Cursor 查 / 設
{"id":"r50", "cmd":"buffer/cursor-get", "buffer-id":"*minibuffer*"}
→ {"id":"r50", "ok":true, "data":{"offset":3}}

{"id":"r51", "cmd":"buffer/cursor-set",
            "buffer-id":"*minibuffer*", "offset":0}

// 在 cursor 處插入文字並推進 cursor
{"id":"r52", "cmd":"buffer/insert",
            "buffer-id":"*minibuffer*", "text":"foo"}

// 在指定 offset 插入（cursor 在該 offset 之前的話不動，之後的話跟著推）
{"id":"r53", "cmd":"buffer/insert",
            "buffer-id":"*minibuffer*", "at":0, "text":"prefix:"}

// 刪除 [from, to) 範圍
{"id":"r54", "cmd":"buffer/delete",
            "buffer-id":"*minibuffer*", "from":3, "to":5}
#+end_src

這些指令是 text engine 的 SHOULD 實作（§7.2）。對 mupdf 之類非編輯型
engine 一律回 =ok:false= + =error: "not supported"=。

*** 5.4 minibuffer/ ── universal input prompt

Minibuffer 是 framework 的單行輸入區（chrome primitive，見 §1.2）。所有
從使用者讀字串的場景——=M-x=、=/=、=C-x C-f=、=M-:=——都共用同一個 widget。

#+begin_src json
// 打開 minibuffer 並設定 prompt
{"id":"r60", "cmd":"minibuffer/open", "prompt":"/"}
→ {"id":"r60", "ok":true}

// 已開啟下更換 prompt
{"id":"r61", "cmd":"minibuffer/set-prompt", "prompt":"Search: "}

// 替換目前文字（completion / history 回填）
// set-text 後 cursor 自動移到文字末尾（Emacs 慣例：set-text 等同
// 「插入並把點放在末尾」，使用者可以接著打字繼續延伸）。v0.7。
{"id":"r62", "cmd":"minibuffer/set-text", "text":"hello world"}

// 關閉（不論使用者送出 / 取消，backend 都應呼叫一次收尾）
{"id":"r63", "cmd":"minibuffer/close"}

// 查詢狀態。response 含 cursor 欄位（codepoint offset，0-based；
// BMP 內 CJK 每字算一個 unit）。v0.7 新增 cursor。
{"id":"r64", "cmd":"minibuffer/get"}
→ {"id":"r64", "ok":true,
   "data":{"open":true, "prompt":"/", "text":"hello", "cursor":5}}
#+end_src

使用者在 minibuffer 中的按鍵會經 =minibuffer-input= / =minibuffer-submit=
/ =minibuffer-cancel= 事件推回 backend（細節見 §六）。

*** 5.5 message/ ── echo area + =*Messages*= buffer

Echo area 是 minibuffer 閒置時的同一條畫面區域，印短訊息；=*Messages*=
是累積所有 message 的 text-engine buffer。

#+begin_src json
// 印一行到 echo area（覆蓋上一條）；自動 append 到 *Messages*
{"id":"r70", "cmd":"message/echo",
            "text":"Saved /tmp/x.pdf"}

// 只 append 到 *Messages*、不打擾 echo area（背景訊息）
{"id":"r71", "cmd":"message/log",
            "text":"Background search: 3 hits in page 5"}

// 清空 echo area（不影響 *Messages* 歷史）
{"id":"r72", "cmd":"message/clear"}
#+end_src

*** 5.6 modeline/ ── window status line

每個 window 底部一條 status line。三段：left（buffer 資訊）、middle（mode
名）、right（位置、百分比等）。

#+begin_src json
// 設定某 window 的 modeline（win-id 省略 = 全域樣板）
{"id":"r80", "cmd":"modeline/set",
            "win-id":"w1",
            "left":  "PDF: paper.pdf",
            "middle":"pdf-mode",
            "right": "p5/42 (12%)"}

// 查詢目前 modeline
{"id":"r81", "cmd":"modeline/get", "win-id":"w1"}
→ {"id":"r81", "ok":true,
   "data":{"left":"...", "middle":"...", "right":"..."}}
#+end_src

v0.4：三段都是純文字。將來可能支援 face / 格式化欄位（如時間、icon）。

** 六、事件參考

Frontend 主動推送，無 =id=。所有事件帶 =frame-id=（事件來源的 OS 視窗）。

*** Minibuffer 事件

Minibuffer 開啟時（=minibuffer/open= 之後），使用者輸入的處理規則：

- **printable 字元** → frontend 把字元 **插入到 cursor 位置**（v0.7 前為
  append 到末尾），推 =minibuffer-input= 事件帶當前完整文字；**不**推
  =key= 事件。Cursor 自動往右移一格。
- **BS** → 刪掉 cursor 左邊那一個 codepoint（cursor 也左移一格），推
  =minibuffer-input= 事件帶更新後文字；**不**推 =key= 事件。空 buffer
  按 BS 仍 consume、不 fallback 到 =key= 事件。v0.7。
- **Left / Right** → cursor 左 / 右移一個 codepoint；**不改文字、不推
  事件**（cursor 移動屬靜默操作，Emacs 慣例。Lisp 端可用 =minibuffer/get=
  問當前 cursor）。邊界（cursor=0 按 Left；cursor=末尾按 Right）no-op。v0.7。
- **Home / End** → cursor 跳到開頭 / 末尾；**不改文字、不推事件**。v0.7。
- **RET** → 推 =minibuffer-submit= 事件帶最終文字；**不**推 =key= 事件。
- **ESC** → 推 =minibuffer-cancel= 事件；**不**推 =key= 事件。
- **其他鍵**（modifier combos、function key 等非上列）→ 推一般 =key=
  事件。這樣 backend 仍能透過 minibuffer-mode keymap 或 global keymap
  處理（例如 =C-g= 取消、=Up/Down= 歷史導覽）。

#+begin_src json
// 每打一個 printable 字元 / BS — 帶當前完整文字
{"event":"minibuffer-input",
 "frame-id":"f1", "text":"hel"}

// RET 送出
{"event":"minibuffer-submit",
 "frame-id":"f1", "text":"hello"}

// ESC 取消
{"event":"minibuffer-cancel",
 "frame-id":"f1"}
#+end_src

設計取捨：cursor 移動鍵（Left/Right/Home/End）刻意不推事件，避免高頻
方向鍵打爆 bridge。需要追蹤 cursor 的 use case 走 =minibuffer/get=
主動查（response 含 =cursor= 欄位）。BS 推事件因為 text 真有變化、
跟一般打字一致。

** 七、Engine Interface Spec

任何人都可以為 Limn 寫 engine。以下是合法 Limn engine 的介面規格。

*** 7.1 MUST 實作

#+begin_src
buffer/open      接受 path 或 url，回傳 buffer-id 與 supports 列表
buffer/close     釋放資源
view/set         更新視埠（至少支援 page、zoom、offset-y）

view/overlays    在視埠上繪製疊加層（rect、line、text，支援 opacity）
                 真實 GUI 模式下 *必須實際繪製* 到 widget；
                 headless / test 模式可只追蹤 layer 數量供 test/snapshot 用
#+end_src

*** 7.2 SHOULD 實作

#+begin_src
buffer/text          文字內容與邊界框（文字類 engine）
buffer/toc           結構/目錄樹
buffer/links         頁面連結
buffer/render        整頁 PNG 渲染
buffer/render-region 矩形 PNG 渲染

buffer/search        多頁文字搜尋（rects page-normalized 0..1）

# 編輯類（text engine 適用，§5.3 後段）
buffer/cursor-get    取得當前 cursor offset
buffer/cursor-set    設定 cursor offset
buffer/insert        在 cursor 或指定 offset 插入文字
buffer/delete        刪除指定 range
#+end_src

engine 對不支援的指令一律回傳 ={"ok":false,"error":"not supported"}=。

#+begin_src
buffer-opened   buffer 成功載入後
error           任何內部錯誤
#+end_src

*** 7.5 Engine 命名慣例

engine 名稱：小寫字母加連字號，如 =mupdf=、=web=、=text=、=sgf=。
對應的 Lisp 封裝使用 CL package，如 =limn/mupdf=、=limn/web=。

*** 7.6 Bundled Engines（frontend 必須 bundle）

任何 Limn frontend 至少 bundle 以下 engine，提供 chrome primitives 與
PDF 基本能力：

- **=text=**：純文字 buffer。最小實作即可（QPlainTextEdit-style）。
  支援 =buffer/text=、=buffer/render=（可選），主要透過 =minibuffer/*=、
  =message/*=、=modeline/*= 三個命名空間間接驅動。**所有 chrome
  primitives**（minibuffer、echo area、modeline、=*Messages*=）都是
  text-engine buffer——這個對稱讓 framework 不必特別處理「框架內部」
  vs「使用者內容」的區別。

- **=mupdf=**：PDF / EPUB 等基於頁的文件。實作完整 §7.1 + §7.2。

=bridge/capabilities= 回應的 =engines= 欄位必須包含這兩個。

** 九、Backend Conventions

本節描述 Backend（SBCL）端的軟性慣例，**不屬於線協議**。線協議完整定義
在 §四到 §七。這裡的東西讓不同的 Limn user code 看起來一致、互通；
若換成別的 backend 語言（理論上可以）也該照樣實作這些慣例。

*** 9.1 Mode 系統

Mode 是 Backend 端的物件，包含：

- 名稱（字串；慣例小寫加 =-mode= 後綴，例如 =pdf-mode=、=search-mode=）
- type：=:major= 或 =:minor=
- keymap（可指向 parent keymap，繼承綁定）
- 可選 =:on-enter= / =:on-exit= hook
- 可選 =:modeline-name=（modeline 顯示用，預設取 mode 名）

每個 buffer 有：
- 恰好一個 major mode
- 一個有序的 minor mode list（由近期啟用到最早啟用）

按鍵查詢順序：
1. buffer 的 minor modes（依啟用順序由新到舊）
2. buffer 的 major mode
3. global keymap

啟用 / 切換 mode 時 backend 應：
1. 觸發舊 mode 的 =:on-exit= hook（若是替換 major mode）
2. 啟動新 mode 的 keymap
3. 觸發新 mode 的 =:on-enter= hook
4. 呼叫 =modeline/set= 更新 modeline 顯示

Mode 與 engine 不同：engine 決定 buffer **裝什麼內容**（PDF、HTML、純
文字），mode 決定 buffer **使用者怎麼互動**。同一個 PDF buffer 可以套
=pdf-mode= 或 =presentation-mode=，內容不變、互動規則換了。

**Mode-buffer 與 wire buffer-id 的對應**：

每個 wire-level buffer（=bridge/engine-load= 或 chrome 自動建立的）在
backend 端對應一個 mode-buffer 狀態。Backend runtime（=limn.lisp= 或
等價物）維護 =buffer-id (string) → mode-buffer (object)= 的映射：

- =bridge/engine-load= 成功 → runtime 建一個 mode-buffer、啟用 engine
  預設的 major mode（如 =mupdf= engine 預設 =pdf-mode=、=text= engine
  預設 =fundamental-mode=）
- =buffer/close= → runtime 移除對應 mode-buffer
- chrome buffer (=*minibuffer*=、=*messages*=、=*echo-area*=) 在
  runtime 啟動時自動建立、各自啟用預設 mode（如 =*minibuffer*= →
  =minibuffer-mode=）

按鍵分派：=key= 事件帶 =win-id= → runtime 查 window 的 active buffer-id
→ 對應的 mode-buffer → 走 §9.1 的 minor → major → global keymap stack。

這層映射是 backend convention、不在線協議內——frontend 對 mode 一無所
知，只透過 =modeline/set= 等 chrome 命令間接看到 mode 名。

**Keymap UX 約定**（使用者寫 init.lisp 時的 API surface）：

對應 Emacs 的 =global-set-key= / =define-key MAP= / =local-set-key=，
backend 必須提供：

#+begin_src lisp
;; 預設綁全域 (≈ Emacs global-set-key)
(limn:bind "C-x C-f" 'find-file)

;; 綁到特定 mode 的 keymap (≈ Emacs (define-key pdf-mode-map ...))
(limn:bind "j" 'next-page :mode 'pdf-mode)
(limn:bind "n" 'next-hit  :mode 'search-mode)

;; 直接給 keymap object，不透過 mode 名查詢
(limn:define-key SOME-KEYMAP "C-g" 'keyboard-quit)

;; 對稱解除
(limn:unbind "j" :mode 'pdf-mode)
#+end_src

action 可以是：
- 一個 =(lambda (event) ...)= 直接綁進去
- 一個 command-name symbol——=limn:bind= 自動 wrap 成 call-interactively
  closure、並 register 到 introspection 的 reverse table 讓
  =where-is-command= 找得到

同 spec 在不同 mode 互不干擾、mode binding 覆寫 global、prefix（multi-key
sequence）在 mode keymap 上正常工作。這些是必須測試釘住的 invariant。

*** 9.2 Interactive 規範

每個 command 應宣告它需要的輸入。Framework 自動從 minibuffer 拿輸入
填進 command 的參數，command body 不直接碰 minibuffer：

#+begin_src lisp
(defcommand my-search
  (:interactive "sSearch: "     ; s = 從 minibuffer 讀字串，prompt 為 "Search: "
   :mode pdf-mode)              ; 限定在 pdf-mode 才生效
  (lambda (query)
    (search-and-jump query)))
#+end_src

Interactive spec 字元（沿用 Emacs）：

| 字元 | 意義                                          |
|------+-----------------------------------------------|
| =s=  | 從 minibuffer 讀一行字串                      |
| =f=  | 讀 file path（未來：minibuffer + completion） |
| =p=  | 接收 prefix arg（如 =5g= 的 5）                |
| =r=  | region（未來）                                |

Command 可以無 interactive spec（不需要外部輸入時）。

**Numeric prefix arg 累進器（v0.7 落實）：**

對應 Emacs 慣例 =5g= → goto-page 5。Framework 在 dispatch key 之前，
看到「無 modifier、無 key-prefix 中、單一數字字元」就累進到內部
accumulator、**不** dispatch；遇到下一個非數字鍵時，把 acc parse 成
integer、在 dispatch 該鍵的 handler 期間 dynamically bind 到
=limn/cmd:*prefix-arg*=：

#+begin_src lisp
(defcommand goto-page (:interactive "p")
  (lambda (n)
    ;; n 自動拿到 *prefix-arg*；無前導數字時 default = 1
    (view/set :page n)))

(limn:bind "g" 'goto-page)

;; user 按 "5g" → n = 5
;; user 按 "42g" → n = 42
;; user 按 "g" 單獨 → n = 1（default）
#+end_src

語意：
- accumulator 只在 dispatch attempt 之後 reset（包括 unbound 鍵也算 dispatch
  attempt、會 reset）
- 數字鍵被攔截不會 fire 任何 binding；若 user 真要把 =5= bind 給 command、
  得搭 modifier（如 =C-5=）避開累進器
- =:interactive "p"= 從 =*prefix-arg*= 拿值；handler body 內若直接讀
  =limn/cmd:*prefix-arg*= 也拿得到

*** 9.3 Init file

啟動時 backend 依序嘗試載入：

1. 環境變數 =$LIMN_INIT= 指定的檔案
2. =~/.limn/init.lisp=
3. =~/.config/limn/init.lisp=（XDG）

擇先存在者載入；都沒有則跳過、不視為錯誤。

Init file 用來定義 mode、綁鍵、加 hook、自訂行為。對應 Emacs 的
=~/.emacs= / =~/.emacs.d/init.el=。

*** 9.4 Introspection

Backend 必須提供下列查詢，讓使用者「即時問系統」：

| 函式                              | 對應 Emacs |
|-----------------------------------+------------|
| =(describe-key spec)=             | =C-h k=    |
| =(describe-command name)=         | =C-h f=    |
| =(where-is-command name)=         | =C-h w=    |
| =(list-modes &optional buffer)=   | =describe-mode= |

這層讓 Limn 變得可學習——任何 key、任何 command 都能即時問它「你是什麼」。

** 十、Undo 模型

*** 10.1 兩層

Limn 的 buffer 比 Emacs 多樣（mupdf、未來 text / web / image / audio
等），不同 engine 自然的 undo 形狀差很多。所以 Limn 採兩層模型，不是
Emacs 的單層 primitive-level：

**Universal command-level undo**（所有 engine 共用）

  任何 =(defcommand foo (:undoable t))= 的命令、body 回傳的 thunk
  被 push 到 session-level =*undo-stack*=。一個 entry = 一個
  使用者按鍵造成的 user-visible 動作。

**Buffer-primitive level undo**（per-engine、optional）

  支援字串編輯的 buffer（text-engine、=*minibuffer*= 等）內部 insert /
  delete / cursor-set 等 primitive 累積到 buffer-local 的 primitive
  list。command 結束時自動摺合成一個 command-level entry——對應 Emacs
  的 =undo-boundary=。

對比：

| Engine               | undoable surface                          | 適用層         |
|----------------------+-------------------------------------------+----------------|
| mupdf                | view state、annotation、bookmark          | command-level  |
| text（未來）          | 字串 insert / delete、cursor              | 雙層           |
| =*minibuffer*=       | 同上                                       | 雙層           |
| web（未來）           | history、scroll；form input               | command + buffer (form) |
| image（未來）         | filter / crop / adjust stack              | command-level  |
| audio（未來）         | effect chain、playback position           | command-level  |

*** 10.2 使用者面 API

| 函式               | 預設綁定 | 行為                                           |
|--------------------+----------+------------------------------------------------|
| =(undo-command)=   | =C-/=    | 退一個 command-level entry                     |
| =(redo-command)=   | =C-?=    | 前進一個                                       |
| =(undo-buffer)=    | =M-/=    | 退一個 buffer primitive（text-like buffer 才有意義） |
| =(redo-buffer)=    | =M-?=    | 前進一個                                       |

非 text-like buffer 上呼叫 =undo-buffer= = no-op + echo "no buffer undo
in <mode>-mode"。預設 binding 跟 =keyboard-quit= 一樣可被 =limn:bind=
覆寫。

*** 10.3 Redo 模型

採 Emacs-style tree：undo 本身是一個 action、進 =*undo-stack*=、redo
**不清空**。對應 =undo-tree.el= 的時間樹。**不是** Vim 早期那種「新動作
清 redo」的線性 stack。

*** 10.4 Scope

cross-buffer：一個 session-level =*undo-stack*=。理由：

- =bridge/win-split= 等改 frame state 不屬於任何單一 buffer
- Emacs 的 =buffer-undo-list= 是「buffer = 一切」的假設下成立；Limn buffer
  只是 engine 內容的容器，不是世界
- 使用者真要 buffer-local 自己寫 macro 限制：=(with-buffer-undo BUF ...)=

*** 10.5 Author 責任

=(:undoable t)= 的 command body 必須回傳：

#+begin_src lisp
;; 一、回傳 thunk：被視作 undo（redo 等同重做 command）
(defcommand goto-page (:interactive "p" :undoable t)
  (lambda (n)
    (let ((old (%current-page)))
      (when (/= n old)
        (%goto-page n)
        (lambda () (%goto-page old))))))    ; ← undo

;; 二、回傳 cons (undo . redo)：明確兩個方向
(defcommand add-annotation (:undoable t)
  (lambda (annot)
    (let ((id (engine-add-annotation annot)))
      (cons (lambda () (engine-delete-annotation id))    ; undo
            (lambda () (engine-add-annotation annot))))))  ; redo

;; 三、回傳 NIL：no-op、不進 undo stack
(defcommand goto-page (:interactive "p" :undoable t)
  (lambda (n) (when (/= n (%current-page)) ...)))
#+end_src

Framework **不替作者算 inverse、不替作者快照 state**。寫不出 inverse 就
不該標 =:undoable=、應該寫成普通 =defcommand=。

** 十一、Bridge Introspection

對應 Emacs 的 =describe-function= 對 subr 的 introspection。Limn 的
「subr-equivalent」是 bridge wire 指令——C++ 端定義、Lisp 端呼叫的
底層原語。Backend 必須提供：

*** 11.1 Primitive registry（C++ 端）

每個 wire 指令在 C++ 端**用統一介面註冊**：

#+begin_src c++
LIMN_CMD("view/set", "Update view state (page/zoom/scroll/rotation).",
         /*required=*/{"win-id"},
         /*optional=*/{"page", "zoom", "offset-y", "rotation"},
         /*since=*/"v0.2",
         cmd_view_set);
#+end_src

C++ 端維護一個 =command_registry= QHash。dispatch 從這個 registry 查表、
不是 if/else chain。

*** 11.2 Introspection wire commands

| =bridge/list-primitives=                         | 回所有 registered command 的 metadata list |
| =bridge/describe-primitive :name STR=            | 回單一 command 的詳細 spec                  |
| =bridge/trace-enable=                            | 開 trace：每次 dispatch emit bridge-trace event |
| =bridge/trace-disable=                           |                                              |

回傳 shape：

#+begin_src json
{"data":[
   {"name":"view/set", "doc":"Update view state...",
    "required":["win-id"], "optional":["page","zoom",...],
    "since":"v0.2"},
   ...]}
#+end_src

*** 11.3 Trace event

開啟 trace 後每個 wire 指令 dispatch 觸發一個事件：

#+begin_src json
{"event":"bridge-trace",
 "cmd":"view/set",
 "args":{"win-id":"w1","page":3},
 "duration-ms":12,
 "ok":true}
#+end_src

backend 可以用 hook 接這個事件做 logging、profiling、debugging。

*** 11.4 Lisp 端對應

| =(limn/introspect:list-primitives)=               | 同 wire =bridge/list-primitives= 的 cache |
| =(limn/introspect:describe-primitive name)=       | 同上                                       |
| =(limn:trace-bridge t/nil)=                       | 包 enable/disable + 註冊 hook 印 trace      |

*** 11.5 SPEC vs code drift detector

整合測試應該斷言：=bridge/list-primitives= 回傳的 cmd 名稱集合 ⊇ SPEC
§5/§6/§7 文件記錄的指令名稱集合。SPEC 漏寫或 C++ 漏實作會被自動抓到。
這是兩件事保持同步的硬性機制——人類靠記憶不可靠。

*** v0.23 Runtime Core — 純 Lisp 執行基礎 (原始 SPEC 草案)

v0.22 已被另一 agent 佔（gap-buffer 前端化）。v0.23 不碰 v0.22 的
範疇、走平行的「runtime infra」軌道。

哲學要點：vanilla-Emacs 的 C-core 寫 process / timer 是因為 Emacs
runtime 就是 C；Limn backend 本身就是個獨立 SBCL，process / timer /
condition / undo / logging 全部**可以純 Lisp 做**、C++ 只需要為
undo 多 emit 一個 event。Lisp 層越厚、未來換 frontend（GTK / 終端
/ web canvas）成本越低。

**** A. =process= primitive — 純 Lisp

底層用 =sb-ext:run-program=。設計對齊 Emacs =make-process=。

- =limn/process:make-process= : =&key name command stdout-buffer
  stderr-buffer sentinel filter env=
  - 回 process object（struct=process= 帶 pid / status / streams）
  - =:sentinel= 在 exit 時 fire、收到 process + exit-code + exit-status
  - =:filter= 在每次 stdout 有新資料時 fire、收到 process + chunk
- =limn/process:process-send-string= proc str
- =limn/process:process-send-eof= proc
- =limn/process:kill-process= proc &optional signal
- =limn/process:process-status= proc → =:run= / =:exit= / =:signal=
- =limn/process:process-exit-code= proc
- =limn/process:shell-command= cmd → 同步、回 =(values stdout stderr exit-code)=
- 全部 wire 事件 =event/process-exit=、=event/process-output=（push 給
  bridge subscriber、與 buffer 整合）

非阻塞策略：每個 process 配一個 SBCL thread 讀 stdout/stderr pipe、
透過 mutex-protected queue 餵到主 event loop dispatch。**不開新
C++ 命令、不動 Qt event loop**。

**** B. =timer= / =async= primitive — 純 Lisp

- =limn/timer:run-at-time= delay-secs callback &key repeat name → timer
- =limn/timer:run-with-idle-timer= idle-secs callback &key name
  - idle 定義 = 從上次 dispatch event 起算 N 秒沒新 event
- =limn/timer:cancel-timer= timer
- =limn/timer:list-timers= → list
- 底層：單一 timer-thread + sorted heap by next-fire-time、wait on
  =sb-thread:condition-wait= with timeout
- 與 bridge 整合：callback 在主 event loop 跑（thread-safe queue
  push）、不在 timer thread 跑（避免 user code race）

**** C. =condition= / debugger — 純 Lisp

- =*debugger-hook*= : function (condition prev-hook) → 預設 print +
  push event/error
- =limn/error:with-error-protection= macro: 包住 user callback、capture

- =event/error= : push 給 frontend (chrome bar 紅字提示)
- =*Backtrace*= buffer (text-only)：trace 寫進 buffer registry、user
  可以開來看
- 不做：full interactive debugger UI（user-land 自己做）

**** D. =undo= / redo — 純 Lisp + 一個 C++ event

C++ 改動只一處：

- =gap_buffer.cpp= insert / delete / replace 在成功 mutate 後 emit
  =event/buffer-modified= 帶 =:buf-id :op :pos :len :before :after=
  - 透過 =LimnBridge::push_event= 走 wire

- =limn/undo:redo= count
- =limn/undo:disable-undo= buf / =enable-undo= buf

**** F. =auto-save= — 建在 v0.23 timer

**** B. =text-properties=

**不變式（架構約束）**：所有 text 修改必須走 Lisp wrapper，不可直接

;; 必須走 wrapper：
(limn/text:insert buf p s)
  ;; → 1. shift interval tree（>= p 的所有 start/end 加 len）
  ;; → 2. 處理 stickiness boundary 語意
  ;; → 3. 呼叫 bridge buffer/insert
#+end_example

**Insert 語意（Emacs 預設 stickiness）：**

新插入文字的屬性由插入點 P 的左邊字元決定，但受 stickiness 控制：

| 情況 | 行為 |
|------|------|
| 在 interval =[S,E)= 中間插入 | 繼承；interval 延伸為 =[S, E+L)= |
| 在右邊界 E 插入（rear-sticky，預設） | 繼承；interval 延伸為 =[S, E+L)= |
| 在左邊界 S 插入（front-nonsticky，預設） | 不繼承；從 S-1 的屬性決定 |
| prop 加了 =front-sticky= | 繼承；interval 延伸到 =[S-L, E)= |
| prop 加了 =rear-nonsticky= | 不繼承；interval 維持 =[S, E)= |

**Delete 語意：** 刪除 =[P, P+L)=：
- 完全在範圍內的 interval → 移除
- 橫跨邊界的 interval → 裁切（保留交集外的部分）
- 完全在 P+L 之後的 interval → start/end 各減 L

**Interval 合併：** 相鄰兩個 interval plist 完全相同 → 合併。每次
=put-text-property= / =remove-text-properties= 後觸發。

**** B. =map!= macro — Doom 風格批次 keymap 定義

逐個呼叫 =limn:bind= 在大 init.lisp 很難讀。=map!= 是純 Lisp macro，
展開成一組 =limn/keys:define-key= 呼叫：

#+begin_src lisp
;; 綁到 mode 的 keymap
(map! :map pdf-mode-map
  "j"   #'pdf-scroll-down
  "k"   #'pdf-scroll-up
  "n"   #'pdf-next-page
  "p"   #'pdf-prev-page)

;; :prefix 縮寫：下面兩個鍵都帶 "g" 前綴
(map! :map pdf-mode-map :prefix "g"
  "g"  #'pdf-first-page
  "G"  #'pdf-last-page)

;; :leader 直接綁到 *leader-keymap*
(map! :leader
  "f f" #'find-file
  "f r" #'recentf-open-files
  "b b" #'switch-to-buffer)
#+end_src

選項語義：

- =:map KEYMAP= — 目標 keymap object
- =:mode MODE-SYMBOL= — 透過 mode 名查 keymap（糖衣）
- =:prefix STRING= — 後續 spec 自動加前綴（可巢狀 =map!= 呼叫）
- =:leader= — 等同 =:map *leader-keymap*=
- action 是 lambda 或 command symbol，自動 wrap call-interactively

=limn:bind= 和 =limn/keys:define-key= 繼續是底層 primitive；
=map!= 只是 macro sugar，不引入新 runtime state。

*** v0.30 Markers + Buffer-local variables ⏭ planned

純 Lisp、零 C++ 改動。補兩個 Emacs C-core 才有、但 Limn 還缺的基本元件——
這兩個元件是其他模組的「地基」：任何「位置」(mark / bookmark / annotation
/ undo entry / search hit) 要在編輯後仍然指對地方、任何 mode 要乾淨地帶
自己的 buffer-scoped state，都得仰賴它們。

**動機**：v0.24 起每個有「offset」概念的模組（mark-ring、bookmark、
annotation、undo position）存的都是 raw integer——使用者在 marker 之前
插一段字，offset 就失準。Emacs 在 C-core 用 marker 解這個問題、每次
buffer mutation 自動 fixup 所有 marker。v0.30 把這層補上。

**** A. Markers — 自動修正的 buffer 位置

API：

#+begin_src lisp
;; 建立
(make-marker)                                  ; → 未指向任何位置的空 marker
(point-marker)                                 ; → 當前 buffer + cursor
(point-min-marker)                             ; → 當前 buffer 起點
(point-max-marker)                             ; → 當前 buffer 終點
(copy-marker MARKER)                           ; → 同位置的新 marker
(copy-marker INTEGER &optional INSERT-TYPE BUF) ; → 從 integer 升級

;; 存取
(marker-position M)                            ; → integer 或 nil（unlinked）
(marker-buffer M)                              ; → buffer-id 字串 或 nil
(set-marker M POSITION &optional BUFFER)       ; 重新指向

;; 插入行為（Emacs 慣例）
(marker-insertion-type M)                      ; :before（預設）或 :after
(set-marker-insertion-type M TYPE)             ; 改變
;;   :before — 在 marker.pos 插入時，marker 不動（留在原位）
;;   :after  — 在 marker.pos 插入時，marker 推到新文字後
#+end_src

**Fixup 規則**（每次 =:event/buffer-modified= 觸發、遍歷該 buffer 的 marker list）：

#+begin_example
Insert at POS, length L:
  for each marker M with marker-buffer == this buffer:
    if M.position < POS:                    不動
    elif M.position == POS:
       if M.insertion-type == :before:      不動
       else:                                M.position += L
    else (M.position > POS):                M.position += L

Delete [FROM, TO):
  for each marker M:
    if M.position <= FROM:                  不動
    elif M.position < TO:                   M.position = FROM   ; clamp 到刪除起點
    else (M.position >= TO):                M.position -= (TO - FROM)
#+end_example

**內部資料**：

每個 buffer-id 對應一個 weakref 集合（=*markers-by-buffer*= : buffer-id
→ set of markers）。weakref 是因為 marker 隨時可能被 GC、不該 leak。
SBCL 用 =sb-ext:make-weak-pointer= 實作；unit-tier 測試可用 simple list
+ manual cleanup（避免引入 SBCL 特定依賴到 unit-tier 框架）。

**整合既有模組**（v0.30 ship 時順手轉換）：

- =limn-mark.lisp= : mark / mark-ring 改存 marker（不是 integer offset）。
  =set-mark= 接受 integer 自動 wrap 成 marker。=mark= 回傳的還是 integer
  (=marker-position=)，保持 API 兼容
- =limn-buffer-undo.lisp= : undo entry 的 position 升級成 marker，
  insert/delete 中段時 undo 記錄不會錯位
- =limn-pdf-mode.lisp= : annotation 開啟時還是讀 fixed rects（sidecar
  存的是固定矩形），但 v0.30 開放 =pdf-annotation-anchor= 槽位給未來
  marker 支援 reflow 文件用——本版只先 plumb，annotation 行為不變

**Marker 與 codepoint cursor (v0.16) 的關係**：

=marker-position= 是 codepoint offset（跟 =buffer/cursor-get= 同單位），
不是 UTF-16 unit、不是 byte。v0.16 釘的 cursor 語意一致——marker 不引入
新單位。

**** B. Buffer-local variables — 通用框架

API（對齊 Emacs，命名直接照搬）：

#+begin_src lisp
;; 宣告全域帶 buffer-local 預設值的變數
(defvar-local *fill-column* 70 "Column to fill at.")
;; 等同 (defvar *fill-column* 70 ...) + (make-variable-buffer-local '*fill-column*)

;; 既有 defvar 後升級
(make-variable-buffer-local '*tab-width*)

;; 寫 buffer-local（在當前 buffer，全域 default 不動）
(setq-local *fill-column* 80)
;; 或顯式
(set-buffer-local-value '*fill-column* 80 BUF-ID)

;; 讀（讀當前 buffer，若無 buffer-local 值落到 default）
(limn/local:get '*fill-column*)                ; 走 buffer-aware lookup
(buffer-local-value '*fill-column* BUF-ID)     ; 顯式指定 buffer
(default-value '*fill-column*)                 ; 拿全域 default、跳過 buffer

;; 查詢 / 解綁
(local-variable-p '*fill-column*)              ; T 若當前 buffer 有 local 值
(local-variable-p '*fill-column* BUF-ID)
(kill-local-variable '*fill-column*)           ; 刪當前 buffer local，落回 default
#+end_src

**實作策略**：

不污染 SBCL 的 =symbol-value=（那要 weave 全 runtime、不可行）。改用顯式
package =limn/local=：

- =limn/local:get SYM= — buffer-aware lookup
- =limn/local:set SYM VALUE= — 寫當前 buffer
- =limn/local:bound-p SYM=

提供 =defvar-local= macro 展開成普通 =defvar=（default）+ 標記 +
=setq-local= macro。內部 hash =*buffer-local-symbols*= (symbol → t)；
=mode-buffer= 結構加 slot =local-vars= (hash symbol → value)。

**Lookup 路徑**：
1. =limn/local:get SYM= 先看當前 mode-buffer 的 =local-vars=
2. 找不到、看該 symbol 是否在 =*buffer-local-symbols*= 且 buffer 有 local
   值（已涵蓋第 1 點）
3. 都沒有、回 =(symbol-value SYM)= 也就是 default

**整合既有模組**：

- =mode-buffer-local-keymap= (v0.19) 改用 =local-vars= 統一管：先
  deprecate 該 slot、改成 =(limn/local:get 'limn/mode:*local-keymap*)=。
  保留舊 accessor 為 backward-compat
- v0.31 syntax tables 跟 coding systems 將以 buffer-local var 表達——這
  是 v0.30 必須先做的理由

**hook 點**：

新事件 =:event/buffer-local-changed= : payload =(:buffer-id :symbol
:old :new)=。可用於 modeline 重繪、debug、user-land 觀察。

*** v0.31 Syntax tables + Coding systems ⏭ planned

純 Lisp、零 C++ 改動。補 Emacs C-core 兩個跟「文字怎麼解讀」相關的元件：

**** A. Syntax tables — 字元文法分類

v0.28 M-f / M-b 寫死「alphanumeric + =_= = word」，這在 prog-mode 是錯的：
=lisp-mode= 裡 =-= 跟 =?= 也是 word；=python-mode= 裡 =_= 是 word；
=fundamental-mode= 跟 =text-mode= 規則又不同。Emacs 用 syntax table 解。

**Syntax class**（精簡 Emacs 集合）：

| 類別 | 字元範例 | 行為 |
|------+----------+------|
| =:word=          | A-Z a-z 0-9 中文 | 屬 word，M-f / M-b 連續吃 |
| =:symbol=        | =-=              | 跟 :word 連在一起構成 symbol (forward-sexp) |
| =:whitespace=    | SPC \t \n        | 分隔 |
| =:open=          | =(= =[= ={=      | 開括號（matched with :close） |
| =:close=         | =)= =]= =}=      | 收括號 |
| =:string=        | =\"= =\'=        | string quote |
| =:escape=        | =\\=             | escape char |
| =:punct=         | =,= =.= =;= =:=  | 一般標點 |
| =:comment-start= | =;= (lisp) =//= (c) | 註解開頭 |
| =:comment-end=   | newline (lisp)   | 註解結尾 |

API：

#+begin_src lisp
;; 建立
(make-syntax-table &optional PARENT)            ; PARENT 預設 *standard-syntax-table*

;; 改 entry
(modify-syntax-entry CHAR CLASS &optional TABLE)
;; e.g. (modify-syntax-entry #\- :symbol *lisp-mode-syntax-table*)

;; 查 entry
(char-syntax CHAR &optional TABLE)              ; → keyword class

;; 動態切換（commands 用）
(with-syntax-table TABLE &body BODY)

;; 預設 / 全域
*standard-syntax-table*                         ; fallback
#+end_src

**Buffer-local**：每個 buffer 有 =*syntax-table*=（buffer-local var、
依賴 v0.30）。Major mode 在 =:on-enter= 設值（=text-mode= 用標準表、
=lisp-mode= 用 lisp 表）。M-f / M-b / M-d / forward-sexp 走當前 syntax
table。

**內部表示**：

不用全 Unicode 大 vector（17M 條目）。用兩層：
- 0–127 (ASCII)：simple-vector of length 128，O(1) lookup
- 128 以上：hash table，未設定 → 繼承 parent → 最終 fallback 預設
  (=:word= for letters / =:punct= 其他)

**整合既有模組**：

- =limn-text-nav.lisp= : =forward-word-offset= / =backward-word-offset=
  改吃 syntax table。預設行為跟現在一致（避免 regression）、mode 可以覆寫
- 新 helper =skip-syntax-forward CLASS-STR= / =skip-syntax-backward= 對齊
  Emacs

**** B. Coding systems — 檔案編碼

目前 =limn-file.lisp:find-file= 走 SBCL 預設 UTF-8，碰非 UTF-8 老檔
（CJK Big5 / GB / Shift-JIS / Windows-1252 / Latin-1）就拋 decode error。

API：

#+begin_src lisp
;; 定義
(define-coding-system NAME
  :encoding ENCODING            ; SBCL external-format keyword
  :bom T                        ; 是否帶 BOM
  :eol :unix / :dos / :mac      ; 行尾類型
  :doc DOC-STRING)

;; 查
(find-coding-system NAME)        ; → coding-system 物件 或 nil
(list-coding-systems)            ; → 已註冊清單

;; 轉換 string
(encode-coding-string STR CODING) ; → byte vector
(decode-coding-string BYTES CODING) ; → string

;; 轉換 region (in-buffer)
(encode-coding-region BUF-ID FROM TO CODING)
(decode-coding-region BUF-ID FROM TO CODING)

;; 偵測
(detect-coding-system BYTES)     ; → coding-system 物件（heuristic）
(detect-coding-region BUF-ID FROM TO)

;; 自動：find-file 用
(set-buffer-file-coding-system BUF-ID CODING) ; buffer-local
*buffer-file-coding-system*                    ; buffer-local var (v0.30)
#+end_src

**Bundled coding systems**（v0.31 ship 時內建）：

| name             | SBCL external-format | 用途 |
|------------------+----------------------+------|
| =utf-8=          | =:utf-8=           | 預設 |
| =utf-8-with-bom= | =:utf-8= + EF BB BF | Windows 慣例 |
| =utf-16le=       | =:utf-16le=        | |
| =utf-16be=       | =:utf-16be=        | |
| =latin-1=        | =:latin-1=         | 西歐 binary-safe |
| =windows-1252=   | =:windows-1252=    | Windows 西歐 |
| =gb18030=        | =:gbk=             | 簡中 |
| =big5=           | =:big5=            | 繁中 |
| =shift-jis=      | =:shift_jis=       | 日文 |
| =euc-jp=         | =:euc-jp=          | 日文 |
| =iso-2022-jp=    | =:iso-2022-jp=     | 日文 mail |

SBCL 部分 external-format 名稱不一致——shim layer 把 Limn name 映射到
SBCL name。少數 SBCL 沒原生支援的（=iso-2022-jp= 等）用 babel：optional
quickload dependency、沒裝就降級成 "fallback to UTF-8 + warning"。

**Auto-detect 啟發**：

#+begin_example
1. 檢 BOM：
   - EF BB BF → utf-8-with-bom
   - FF FE    → utf-16le
   - FE FF    → utf-16be
2. 試 UTF-8 valid：if (sb-ext:octets-to-string bytes :utf-8) 不拋錯 → utf-8
3. ASCII-only：utf-8
4. heuristic：
   - 高位 bit set 但 UTF-8 invalid → 看 file-coding-system-alist
     (副檔名 / 路徑前綴) 預設
   - 沒設定 → fallback windows-1252（西歐 binary-safe）
5. 使用者 explicit override via prefix arg：C-u C-x C-f → minibuffer
   讀 coding system 名稱
#+end_example

**find-file 流程**（取代當前實作）：

#+begin_example
1. 讀整個 file as octets
2. detect-coding-system → CODING
3. decode-coding-string → buffer text
4. buffer/load-string + cache buffer-file-coding-system
5. find-file-hook
#+end_example

**save-buffer 流程**：

#+begin_example
1. 拿 buffer text + buffer-file-coding-system
2. encode-coding-string → octets
3. write octets to file
4. before-save-hook / after-save-hook
#+end_example

*** v0.32 Current buffer + save-excursion + narrow-to-region ⏭ planned

純 Lisp、零 C++ 改動。補 Emacs 命令寫法的核心控制流：=*current-buffer*=

macro、=narrow-to-region= / =widen=。

**動機**：Emacs elisp 命令九成都用 =save-excursion=「做完事情把 point 還

**** B. Overlay 資料層（=limn-overlays.lisp= 新檔）

跟 text-properties 的差異：overlay 是獨立 range object、不黏 text。

API：

#+begin_src lisp

(overlay-get OV PROP)

(overlay-end OV)
(overlay-buffer OV)
(delete-overlay OV)
(move-overlay OV NEW-START NEW-END &optional NEW-BUF)
(overlays-in START END &optional BUF) ; → list

(overlay-properties OV)            ; → plist

**** A. Vendor cl-ppcre

引入方式（避免讓使用者再裝 quicklisp）：

3. =backend/limn-regex.lisp= wrap 成 Emacs-style API、不直接 export cl-ppcre

**** B. Emacs-style API

#+begin_src lisp
;; In-buffer search（吃 *current-buffer*）
(re-search-forward REGEX &optional BOUND NOERROR COUNT)
(re-search-backward REGEX &optional BOUND NOERROR COUNT)
(looking-at REGEX)                  ; at point
(looking-back REGEX &optional LIMIT)
(re-search-in-buffer REGEX BUF-ID)  ; explicit buffer
(replace-match REPLACEMENT &optional FIXEDCASE LITERAL)

;; String operations
(string-match REGEX STRING &optional START)
(replace-regexp-in-string REGEX REPLACEMENT STRING &key fixedcase literal)
(split-string STRING &optional SEPARATOR-REGEX OMIT-NULLS)

;; Match data (after a match)
(match-string N &optional STRING)   ; group N capture
(match-beginning N)                 ; position
(match-end N)
(match-data &optional INTEGERS)     ; raw
(set-match-data DATA)
#+end_src

回傳值規範對齊 Emacs：=re-search-forward= 找到 → 把 point 移到 match
end、回 point；找不到 → 看 NOERROR：nil 拋 =search-failed=、t 回 nil、
其他 (e.g. 'limit) 回 nil 但 point 不動。

**** C. Emacs regex syntax 相容

Emacs 跟 PCRE 大方向同但細節差：
- Emacs：=\\(group\\)= / =\\b= / =\\w= / =\\<= / =\\>=
- PCRE：=(group)= / =\b= / =\w= / no =\<=

兩條路：
1. **語法 shim**（=emacs-regex-to-pcre=）：把 Emacs syntax 翻譯成 PCRE
   再餵 cl-ppcre。優：使用者寫法跟 Emacs 一樣
2. **直接 PCRE**：=re-search-forward= 直接吃 PCRE 語法、文件清楚標明
   差異。優：實作簡單、無翻譯 bug

v0.34 走 **path 1**——保 Emacs 慣例。translator 是 ~50 行純 string
manipulation；測試覆蓋 Emacs regex 大全：=\\(...\\)=、=\\|=、=\\b=、
=\\<=、=\\>=、=\\=`、=\\=`、=\\=B=、=\\w=、=\\W=、=\\s-=、=\\sw= 等。

**** D. =limn-search.lisp= 升級

**** A. =query-replace= — M-%

#+begin_src
M-%          start query-replace
M-x query-replace-regexp     start regexp 模式

y / SPC      replace this, move to next
n / DEL      skip this, move to next
!            replace all remaining
q / RET      quit
.            replace this then quit
,            replace this and pause for confirmation
^            go back to previous match

**** B. Indent 系統

| API | 行為 |
|-----+------|
| =(indent-to COL)= | 從 point 補 SPC / TAB 到 column COL |
| =(current-column)= | 拿 point 的視覺 column（TAB 跨 *tab-width*、CJK = 2） |
| =(move-to-column N &optional FORCE)= | 把 point 移到 column N |
| =(back-to-indentation)= | 移到行首第一個非空白字元 |
| =(indent-line-function)= | buffer-local function（v0.30），預設 =indent-relative= |
| =(indent-region FROM TO)= | 每行呼叫 indent-line-function |
| =(indent-rigidly FROM TO COUNT)= | 每行往右移 COUNT column |

Buffer-local vars（v0.30 依賴）：
- =*tab-width*= 預設 8
- =*indent-tabs-mode*= 預設 t（用 TAB；nil 用 SPC）
- =*fill-column*= 預設 70（給 =fill-paragraph= 用、本版只 plumb）

新 keymap entry（text-mode）：
- TAB → =indent-for-tab-command=
- C-j → =newline-and-indent=

**** C. =current-column= — 字寬 awareness

純函式 =(char-display-width CHAR)=：
- ASCII printable → 1
- TAB → 動態：到下一個 tab-stop（=tab-width=）
- newline / CR → 0
- CJK fullwidth → 2
- emoji → 2（最常見 widechar 規則；exact 走 East Asian Width 表）
- 其他 control char → 顯示 =^X= 算 2、或 hex 算 4（看 buffer-display-table，本版固定 control = 2）

=(current-column)= 從行首掃到 point、累 =char-display-width=。
=(move-to-column N FORCE)=：找到目標位置；FORCE = 必要時補 SPC / 拆 TAB。
