* ibuffer 設計

** 架構：vtable + 純 state，仿 ~limn-occur~

整個模組分三層：

1. *純資料層*
   - ~ibuffer-row~ struct：~id path engine mode~
   - ~ibuffer-state~ struct：~rows current marks sort-key filter ibuffer-buf-id~
   - ~*ibuffer-state*~ 是單例（一個 ~*Buffer List*~ 而已）
2. *純邏輯層*
   - ~collect-rows~ / ~sort-rows~ / ~filter-rows~
   - ~format-ibuffer-results~ / ~format-ibuffer-line~ / ~format-mark~
   - ~next-row~ / ~prev-row~ / ~mark-set~ / ~mark-clear~ / ~unmark-all~
   - ~render~（呼叫 vtable 把 content 推出去 + 移 cursor）
3. *I/O vtable*
   - ~*ibuffer-write-fn*~ — 把 content 寫到 ~*Buffer List*~（預設用 ~buffer/text + buffer/delete + buffer/insert~ 重置）
   - ~*ibuffer-switch-fn*~ — 切到目標 buffer（預設 ~buffer/show~）
   - ~*ibuffer-save-fn*~ — S mark 執行（預設 ~buffer/save~）
   - ~*ibuffer-kill-fn*~ — D mark 執行（預設 ~buffer/close~ + ~limn/buffer:unregister~）
   - ~*ibuffer-cursor-fn*~ — 移 cursor（預設 ~buffer/cursor-set~）

vtable 是 dynamic var，install 時 setf 成 wire-talking lambda，unit test progv-bind 成 mock。

** ibuffer-mode 的 keymap

| key             | command                          |
|-----------------+----------------------------------|
| ~n~ / ~<down>~  | ~ibuffer-next-line~              |
| ~p~ / ~<up>~    | ~ibuffer-prev-line~              |
| ~RET~ / ~f~     | ~ibuffer-visit-buffer~           |
| ~d~             | ~ibuffer-mark-for-delete~        |
| ~s~             | ~ibuffer-mark-for-save~          |
| ~u~             | ~ibuffer-unmark~                 |
| ~U~             | ~ibuffer-unmark-all~             |
| ~x~             | ~ibuffer-do-execute~             |
| ~g~             | ~ibuffer-revert~                 |
| ~S~             | ~ibuffer-sort-by~                |
| ~/~             | ~ibuffer-filter-by-substring~    |

~q~ *刻意不綁*（見 [[*為什麼 ~q~ 不綁][為什麼 ~q~ 不綁]]）。

離開 ibuffer 的方式：
- ~RET~ / ~f~ 在某一行 → 切到那個 buffer（自然離開）
- ~M-x switch-to-buffer~ → 自選一個切過去

** *Buffer List* 是 chrome buffer

加進 ~limn-runtime.lisp~ 的 ~*chrome-buffer-modes*~：
#+begin_src lisp
("*Buffer List*" . ,(intern "IBUFFER-MODE" :cl-user))
#+end_src

這個 symbol resolution 是 lazy 的（cl-user 包 ~ibuffer-mode~ symbol 在 limn-runtime 編譯時被 ~intern~ 進去，但 mode 物件本身是 limn-ibuffer.lisp 載入時才 ~define-mode~ 註冊）。~init-chrome-buffers~ 有 ~(when (find-mode ...))~ guard，未註冊就 no-op，無 race。

** *Buffer List* 自己會出現在 list 裡

像 Emacs ibuffer 一樣，~*Buffer List*~ 自己也是一個 text-engine buffer，所以也會出現在表格裡。Wire id 一般是 ~t1~，path 是空字串顯示成 ~<no file>~。這是預期行為，不要 exclude。

** Render 格式

#+begin_example
   M  ID                ENGINE   PATH
>  D  b1                mupdf    /tmp/zeta.pdf
      t1                text     <no file>
   S  t2                mupdf    /tmp/alpha.pdf
#+end_example

欄位：
- 1 char cursor 欄（~>~ 表示當前 row）
- 2 char mark 欄（~D ~ / ~S ~ / ~DS~ / ~  ~）
- 17 char ID
- 8 char ENGINE
- PATH

header 用 ~format-ibuffer-line~ 同樣 format string 自動生成，欄寬機械同步。

* limn:call sync-shim 補完整

** 為什麼這個改動跟 ibuffer 一起走

ibuffer 嚴重依賴 ~limn/buffer~ 跟 ~*window-active-buffer*~ 真的反映 wire 端最新狀態。我們在 dogfood 過程中發現現有 sync 只覆蓋 ~bridge/engine-load~，導致：

1. ~buffer/load-file~ 後 ~limn/buffer~ 的 path 還是 engine-load 時的空字串 → ibuffer 顯示 ~<no file>~ 即使檔案載好了
2. ~buffer/show~ 不更新 ~*window-active-buffer*~ → 按 ~n~ 等鍵 dispatch 到舊 buffer 的 mode-buffer，鍵被吃掉 user 看不到視覺反應
3. ~buffer/close~ 不從 ~limn/buffer~ 拔掉 → ibuffer 列幽靈 buffer
4. ~%on-buffer-opened~ event handler 永遠覆寫 major mode 跟 window active → 如果高階指令（M-x ibuffer）已經 explicit 設好，event 晚到一秒就把它清掉

這些其實都是 architecturally 應該存在的 sync，pre-v0.40 因為沒有需要才沒做。ibuffer 是第一個踩到這些洞的功能，所以順便補。

** ~call~ 函數的 sync-shim（~backend/limn.lisp~）

從一個 ~when~ 分支擴張成 4 個 case：

| wire cmd                | sync 動作                                                  |
|-------------------------+------------------------------------------------------------|
| ~bridge/engine-load~    | 註冊新 buffer 進 ~limn/buffer~ + 設 ~*window-active-buffer*~ |
| ~buffer/load-file~      | 透過 ~(setf buffer-path)~ 更新 ~limn/buffer~ entry 的 path  |
| ~buffer/show~           | 設 ~*window-active-buffer*[win-id] = bid~                  |
| ~buffer/close~          | 從 ~limn/buffer~ unregister                                |

實作上拆成 helper ~%sync-after-call~，包在 ~handler-case~ 裡，失敗只印 ~*error-output*~ 不會打斷 ~call~ 回應。

** ~%on-buffer-opened~ race guard（~backend/limn.lisp~）

兩條新 guard：

1. *不覆寫已存在的 major mode*
   #+begin_src lisp
   (already-set (and existing major-of
                     (funcall major-of existing)))
   (when (and (not already-set) ...)
     (funcall activate mb mode-name))
   #+end_src
   情境：~M-x ibuffer~ 先 ~bridge/engine-load~ 拿到新 bid，~%enter-ibuffer~ 隨即在 bid 的 mode-buffer 上 activate ibuffer-mode。Pump thread 後到的 ~buffer-opened~ event 不會把 ibuffer-mode 換回 text-mode（engine 預設）。

2. *不覆寫已設好的 window active buffer*
   #+begin_src lisp
   (let ((current (and get-active (funcall get-active wid))))
     (when (or (null current) (equal current bid))
       (funcall set-active wid bid)))
   #+end_src
   情境：~M-x ibuffer~ 內部開了 ~/tmp/foo.txt~（為了讓你看到），然後 ~buffer/show~ ibuffer 自己拉回前景。Pump thread 後到的 ~buffer-opened~ event for ~/tmp/foo.txt~ 不會把 active 從 ibuffer 改回 foo.txt。

** Sync-shim 也讓其他 caller 受益

不只 ibuffer。任何用 ~buffer/show~ 切 buffer 的指令都會自動讓 dispatch 跟得上，避免 keys 路到舊 buffer 的 mode-buffer。任何 ~buffer/load-file~ 後，~switch-to-buffer~（讀 wire ~buffer/list~）跟 ibuffer（讀 ~limn/buffer~）都會看到正確 path。

* 為什麼 ~q~ 不綁

** 發現過程

dogfood 走到「M-x ibuffer → q 切回 PDF」這步時：

- ~%quit~ 確實被執行（trace ~[ibuffer] %quit prev="b1" target="b1"~）
- ~buffer/show "b1"~ 也確實送了出去（~view/get~ 回 ~"b1"~）
- ~*window-active-buffer*["w1"] = "b1"~ 也同步好了（dispatch 接下來的鍵路到 pdf-mode）

但 Qt *視覺上看到的還是 ibuffer 表格*。

我們在 worktree 編了一版 C++ patch（在 ~main_widget.cpp~ 的 ~show_pdf_view~ / ~show_text_view~ 裡顯式 ~hide()/show()/raise()~ 對方 widget），用 headless test 確認 wire state 跟 Lisp state 都正確，視覺問題只剩 Qt 端。

** 為什麼不夾帶 C++ patch

最後決定*不把 C++ patch 帶進 ibuffer 這個 branch*：

1. *scope creep*：~show_pdf_view~ 影響所有 text↔pdf 切換（不只 ibuffer），是 sioyek 端獨立的 paint 議題
2. *risk surface*：C++ paint 邏輯沒有 unit test framework，需要視覺驗證；不該跟著 ibuffer 的 Lisp 邏輯一起被審查
3. *ibuffer 不需要 q 也是完整的*：~RET~ / ~f~（visit row）跟 ~M-x switch-to-buffer~ 已經提供「離開 ibuffer」的所有實際工作場景

* 已知 limitation

- ~q~ 不綁 ibuffer-quit（見上）
- ibuffer 表格的 column 寬度是 hardcoded（ID 17 char、ENGINE 8 char）；超長 path 不會 wrap、超長 ID 會把 ENGINE 推開
- sort 跟 filter 都走 minibuffer，沒有 single-key cycle
- 沒有 ~o~ (visit-other-window)，因為目前 sioyek 只有 w1
- ibuffer 自己也會出現在 list 裡，使用者按 ~d~ + ~x~ 在那一行會把 ibuffer 自己 kill 掉 → 已知行為，未來可以加保護
